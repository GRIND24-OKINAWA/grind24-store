# GRIND24 OLD SPICE STORE — 開発スターター

Next.js + Stripe Checkout + Supabase。黒×赤のスマホ対応ショップ、3商品、カート、店頭受取、全国発送（送料は仮）、決済、Webhook、在庫引当と注文DBを含みます。

**重要：これは本番公開前の開発スターターです。現時点で販売可能な完成品ではありません。** 特に法令対応、管理画面、配送通知、返品・返金、決済失敗/タイムアウトの在庫回復、支払済み確認、注文確認メール、プライバシー表示、実商品の画像/説明、実送料が未完成です。

## 起動
1. Node.js 20以上を用意。`npm install`
2. Supabaseの新規プロジェクトを作り、SQL Editorで `supabase/schema.sql` を実行。
3. `inventory` の stock を実在庫に更新。未仕入れなら0のまま。
4. `.env.example` を `.env.local` にコピーし、Stripeテスト鍵、Supabase URLとservice role key、サイトURLを設定。秘密鍵はブラウザに絶対公開しない。
5. `npm run dev` で `http://localhost:3000` を開く。
6. Stripe CLIで `stripe listen --forward-to localhost:3000/api/webhook` を実行し、表示された `whsec_...` を設定。
7. Stripeテストモードで決済し、Webhookで `orders.status=paid` に変わることを確認。

## 実装済み
- 商品データは `lib/products.ts` で編集。**価格は必ずサーバー側で決定**。
- `/api/checkout` はStripe Checkout Sessionを作成。商品数制限・DBの在庫予約あり。
- `/api/webhook` はStripe署名を検証し、支払成功で注文を確定。期限切れで在庫戻し。
- `supabase/schema.sql` はDBのRLSを有効化し、サービスロールのみからアクセスする設計。

## 公開前に必須の追加作業
1. **販売権限と法令**：PX購入品の商業転売を前提にしない。適法な国内流通品の仕入れ先、化粧品/医薬部外品の区分、表示・広告を確認。
2. **注文管理**：管理者ログイン（Supabase Auth等）、注文一覧、在庫追加、発送済み/受取済み更新、追跡番号、返品・返金フローを構築。管理者トークンだけで公開しない。
3. **注文確認**：決済完了メール、店頭受取案内、発送通知をメールサービスで送信。
4. **送料**：コード内の全国一律800円は仮。沖縄からの実費を調べ、地域別送料に変更する。Stripeの配送先情報がWebhookで正しく記録されるか使用APIバージョンでテスト。
5. **在庫・決済の競合**：予約期限・決済遅延・Webhook再送・非同期支払い・払い戻しをテスト。現行の `mark_order_paid` は重複Webhookでエラーを返すので、同じセッションの再送を成功扱いにする冪等化が必要。Checkout Session作成後にDB更新が失敗したケースも手動照合すること。
6. **個人情報保護**：特定商取引法表示、プライバシーポリシー、返品・配送条件、問い合わせ先、個人情報の保持・削除方針を整備。
7. **公開**：GitHub private repository → Vercelへインポート → 環境変数設定 → 独自ドメイン設定 → Stripe本番Webhook URL `https://yourdomain/api/webhook` 登録 → 本番の少額テスト。
8. **ブランド表示**：OLD SPICEは他社商標。公式ショップと誤認させない表示、商品写真・ロゴの使用権を確認。
